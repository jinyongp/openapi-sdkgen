# Go import 경로 자동 추론 리뷰

대상은 `4785933`의 변경 파일 19개와 이 리뷰의 수정 사항이다. 검토와 재검증을 완료했다.
모든 수정은 `apply_patch`로 적용했고 포맷은 프로젝트 명령으로 맞췄다.

## 유지한 계약

- 명시 CLI 값 > 명시 설정 값 > 출력 위치의 가장 가까운 모듈에서 추론.
- 빈 값을 명시하면 오류다. 출력 없는 검사에서는 import 경로를 명시해야 한다.
- 생성기 코어에는 확정된 경로만 전달한다. 생성 시 Go 실행 파일을 요구하지 않는다.
- 사용자 모듈 파일과 기존 출력 소유권 경계를 유지한다.

## 발견 및 수정

1. 모듈 경로 바로 뒤에 붙은 `//` 주석을 식별자의 일부로 읽어 유효한 선언을 거부했다.
   슬래시와 인접 토큰을 처리하면서 표준 스캐너의 주석 인식을 유지하도록 수정했다.
2. 백틱 모듈 경로와 따옴표로 감싼 `module` 키워드를 허용했다. 실제 Go 도구는 두 형식을
   거부한다. 모듈 경로의 큰따옴표 문자열만 해석하고 키워드 원문은 유지하도록 수정했다.
3. 심볼릭 링크 뒤의 `..`를 먼저 정리해 다른 모듈을 선택했다. 실제 경로를 먼저 해석하고,
   CLI의 생성·검사·증분 갱신도 같은 물리 경로를 사용하도록 연결했다. 추론만 수정했을 때
   `--check`가 다른 위치에서 매니페스트를 찾는 실패도 재현하고 해결했다.
4. 자동 추론으로 전환한 문서가 여전히 고정 import 경로를 무조건 사용하도록 안내했다.
   시작하기와 이름 있는 클라이언트의 한·영 설명에 실제 모듈 접두사를 사용하도록 명시했다.

## 검토 범위와 반복 검증

- 모듈 선언 파싱: 일반·큰따옴표·괄호·CRLF·주석·중복·잘못된 선언을 검토했다.
  호환성 사례는 실제 `go mod edit -json` 결과와 비교한다.
- 출력 경로: 새 폴더·상대 경로·중첩 모듈·심볼릭 링크·부모 경로를 검토했다.
  실제 생성 후 자동/명시 경로의 검사와 증분 갱신을 재실행했다.
- 출력 루트의 심볼릭 링크가 생성·검사·증분 갱신에서 계속 거부되는지 확인했다.
- 설정 우선순위, 빈 값, fingerprint, 생성기 경계, 도움말, README, 한·영 안내와 계획을 검토했다.
- 첫 회귀 실행에서 주석과 잘못된 모듈 선택을 재현했다. Go 도구 비교에서 두 잘못된
  선언의 허용을 재현했다. 후속 통합 실행에서 매니페스트 조회 실패를 재현했다.
  수정 후 관련 테스트와 전체 영향 범위 검사를 통과했고 재검토에서 남은 결함은 없었다.

## 최종 검증

- 전체 `cmd/openapi-sdkgen`, `internal/generator`, `internal/output` 테스트 통과.
- Go 포맷 검사와 생성기 빌드 통과.
- 문서 빌드와 렌더링된 링크 검사 통과: 공개 페이지 114개, 기존 경로 52개, 앵커 430개.
- 실행 검증 환경은 WSL/Linux다. Windows의 심볼릭 링크 동작은 이 세션에서 실행하지 않았다.
- SDK 런타임과 다운로드 예제 소스는 수정하지 않았다.
