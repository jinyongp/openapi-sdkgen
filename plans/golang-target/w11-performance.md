# W11 성능·플랫폼 검증 기록

상태: 검증을 켠 타입 스트림을 포함해 모든 필수 측정 완료.
모든 수치는 내부 로컬 측정이며 공개 성능 수치나 언어 간 우위가 아니다. 공개 수치는
GitHub Actions 측정과 해당 run 링크가 필요하다. 원시 결과는 private
`/tmp/sdkgen-go-implementation/w11-final-*/`에 보관한다.

## 측정 기준

생성·빌드·플랫폼·제공자 측정은 [고정 측정 소스](w11-final-code.json)의 SHA256
`640d6b982c9c9e669fe08a84d507e427152bc50126f8b8ff0c2745f28590c3ad`에서 수행했다.
최종 typed runtime은 [완료 소스](w11-verified-code.json)의 SHA256
`1e7c3b09d00dab78f12159ce6082fc1bf4f50eb02d7fd048d865729ef6e187c5`에서 다시 수행했다.
차이는 EN/KO RequestID 예제와 선택 성능 명령의 스트림 측정/README 4개 파일뿐이다.
생성기·SDK 런타임·나머지 워크로드는 같으며 [적용성 검토](w11-verified-applicability.json)에
원래 결과의 재사용과 새 검사 5개를 구분했다. 실패한 helper 중복 삽입 시도의 소스/로그도 보존했다.
Go 1.27.2, CGO 0, GOWORK off, GOTOOLCHAIN local로 실행했다. race만 CGO 1을
사용한다. 입력·생성기·생성물·바이너리 hash, 정확한 argv/환경 플래그/exit code,
원시 stdout/stderr와 GNU time peak RSS를 보존한다. 무거운 측정은 순차 실행했다.
baseline HTTP/JSON도 반복마다 새 요청을 구성하며 SDK 검증은 켠다.

## 런타임

실제 생성 SDK 46개 조건을 각각 5회 측정했다. 기본 HTTP/JSON·일반/Raw/오류,
1KiB/1MiB/16MiB JSON·중첩·재귀·oneOf·추가 속성, XML namespace·분기,
1MiB/64MiB multipart, gzip/deflate/br/zstd/chain, 1000/100000항목·분할 청크·
느린 소비자, 정규식 5종, 인증 제공자·코덱의 1/8/64 동시 호출을 포함한다.
최초 바이트/항목 지연, 할당, 처리 시간은 별도 지표다. multipart reader의 read/close는
정확히 한 번인지 검사한다. forced-GC live heap/대형 JSON GC와 별도 mutex/block profile,
동시 호출 race까지 9개 명령이 통과했다. 프로파일 실행 수치를 일반 5표본에 섞지 않았다.

| 소비 경로 | ns/op 중앙값 [최소–최대] | B/op 중앙값 | allocs/op 중앙값 |
| --- | ---: | ---: | ---: |
| `http-json-16` | 1054 [1027–1128] | 1755 | 16 |
| `do-16` | 4129 [3989–4205] | 6904 | 65 |
| `raw-16` | 3953 [3914–4008] | 6904 | 65 |
| `error-16` | 4725 [4627–4789] | 8440 | 77 |

이는 같은 JSON 기대값의 기본 HTTP/JSON 대비 SDK 추가 비용이며 네트워크 지연 측정이 아니다.
공개 `Events().Stream()`의 요청 구성·schema 검증·DTO 변환을 포함해 측정했다.
forced-GC typed stream live heap 증분은 1000항목 8536B, 100000항목 13184B였다.
일정 크기 프레임을 항목 수만큼 누적하지 않는 실행 근거이며 모든 입력의 고정 heap 보장은 아니다.
압축 해제기는 별도 history window를 보유한다. 개별 코딩/크기의 실제 live heap은 runtime
원시 진단에 보존했다. SDK 프레임 상한과 decoder window를 혼동하지 않는다. 잘못된 항목이
공개 typed Stream에서 거부되는지 먼저 확인했다. 기존 framing-only 표본은 최종 SDK 측정으로 사용하지 않는다.

## 소비자 빌드와 도달성

각 소비자를 5회 생성하고 빈 전용 GOCACHE의 cold 5회와 같은 캐시의 warm 5회를
측정했다. 모든 바이너리를 실행하고 unstripped 심볼·의존 패키지와 별도 stripped 빌드도
보존했다. 총 117개 명령이 통과했다. named는 Todo와 XML/stream/regex 두 진입점의
합집합을 생성한 뒤 Todo만 import한다. 단일 진입점 생성과 혼동하지 않는다.

| 소비자 | cold초 중앙값 [최소–최대] | warm초 중앙값 [최소–최대] | 원본 바이너리 B |
| --- | ---: | ---: | ---: |
| full-static | 5.334 [5.006–5.498] | 0.234 [0.232–0.250] | 10569455 |
| selected | 4.775 [4.720–4.845] | 0.224 [0.217–0.227] | 10506568 |

full-static/named에서 stream·Pattern.Match·metadata 실행 심볼과 XML decoder는 제거됐다.
정규식 의존성의 초기화 심볼 18개는 남았다. selected에는 해당 외부 의존 패키지 자체가 없다.
dynamic에는 operations 심볼 160개와 stream·Pattern.Match가 남았다. metadata는 어느
소비자도 import하지 않았으므로 동적 선택이 metadata도 유지한다고 주장하지 않는다.
공유 IsXMLMedia 같은 미디어 분류 경로는 별도다. 정확한 의존 목록과 nm 결과를 확인했으며
바이너리 크기만으로 제거 성공을 판정하지 않았다. 이 작은 fixture의 시간을 일반화하지 않는다.

## 플랫폼과 원본 제공자

generated SDK와 server/runtime을 CGO0으로 Linux/macOS/Windows amd64/arm64에
교차 빌드했다. Linux amd64만 실제 실행했고 playground WASM도 빌드했다. 10개 명령이
통과했다. 다른 OS에서 실제 실행했다는 뜻은 아니다.

원본 제공자 7개의 full/선택1/선택10 각 5회, 총 105표본과 준비 명령 2개가 모두
통과했다. SHA256/git blob pin을 검사하고 full의 실제 공개 방출 경로에서 선택한다.
각 조합의 출력은 5회 모두 같았고, full 출력은 별도 원본 39건 감사의 hash와도 일치한다.

## 실패 진단과 재측정 경계

최초 Cloudflare300초 timeout/약10GiB live heap은 재귀 DTO 무한 확장 결함의 진단이다.
활성 객체/validator 포인터 연결 뒤 원본 전체 방출이 통과했다. Graph 최초2GiB/300초 및
5GiB/300초 실패를 보존한다. 최종 표본과 다른 CPU/heap/deadline 조건의 실행은 속도 개선
비율로 비교하지 않는다. DigitalOcean 선택의 기존 W140 생략 경로를 고른 실패, VCS 조회
실패, 최초 baseline/named 구성의 혼동된 실행도 보존하며 최종 결과에 섞지 않는다.

[구조화한 완료 측정](w11-performance.json)은 다섯 모드의 원시 위치·중앙값·범위·해시와
정확한 소스 적용성을 연결한다. typed stream 보완 스크립트가 helper를 중복 삽입해 발생한
첫 compile 실패는 `w11-complete-runtime-check.json`과 해당 source/로그에 남겼다. 중복을
제거한 새 immutable source에서 runtime 9개 명령과 영향 문서·옵션·diff를 다시 통과했다.
