# Go 타깃 측정 기록

2026-10-19에 W11 측정 원본과 후속 TypeScript 비교 결과를 저장소에 보존했다.
기존 계획의 완료 기록과 소스 매니페스트는 당시 관측을 나타내므로 변경하지 않았다.

## 결과 찾기

- [TypeScript와 Go 비교표](provider-comparison.md): 전체 생성과 동일한 10개 경로 선택, 조건별 5회.
- [구조화된 비교 결과](provider-comparison.json): 시간 중앙값·범위, 최대 RSS, 파일 수·바이트와 출력 해시.
- [W11 전체 성능 집계](w11-performance.json)와 [기존 해석](../../w11-performance.md): 런타임, 빌드, 생성, 플랫폼, 제공자 측정.
- [원본 인덱스](index.json): 실행별 종료 코드, 원래 파일 경로, 압축 파일·각 구성 파일의 SHA256.
- [문서 검토와 검증](docs-review.md): Go 추가 범위의 문서 작업과 이번 보완.

## 보존 범위

W11 결과 디렉터리 16개와 후속 TypeScript 비교 디렉터리 1개를 보존했다.
총 659개 명령 기록에는 빌드 준비, 재측정, 실패, 제공자 소비자 검증도 포함된다.
이를 서로 다른 659개 성공 벤치마크로 해석하면 안 된다.
원본 2,263개와 초기 Graph·Cloudflare 진단 26개를 합친 2,289개 파일이
실행별 압축 파일 18개에 들어 있다. 압축 크기는 합계 약 68 MiB다.

각 실행의 `results.json`, `basis.json`, 원시 stdout/stderr, GNU time 결과,
제공자별 보고서, CPU·heap 프로파일과 진단 요약을 원래 바이트 그대로 보존했다.
프로파일과 실패 기록은 대표 성능 표본과 구분한다. 최종 판정에는 기존
[W11 집계](w11-performance.json)가 지정한 실행을 사용한다.

생성기·소비자 실행 파일, 생성 SDK 트리, 내려받은 원본 명세와 도구 캐시는 포함하지 않는다.
대신 원래 입력 pin, 소스·생성물·실행 파일의 해시, 명령과 런타임 플래그를 보존한다.
모든 과거 실행 파일이나 소스 버전의 바이트까지 보관했다는 뜻은 아니다.
기록 안의 `/tmp`와 `.tmp` 경로는 당시 실행 위치다. 원본 경로가 없어져도 `index.json`의
`archive`와 `archiveMember`로 보관 위치를 찾을 수 있다.

## 비교 조건과 한계

두 타깃 모두 같은 제품 소스·고정 명세와 `server` 추가 기능을 사용했다.
`metadata` 추가 기능은 사용하지 않았다. Go 1.27.2, CGO 비활성화,
`GOMAXPROCS=2`, `GOMEMLIMIT=5GiB` 조건이며 조건마다 별도 프로세스로 5회 실행했다.
선택 생성은 기존 Go 결과에 실제 방출된 경로 중 정렬한 앞 10개를 양쪽에 동일하게 적용했다.
TypeScript 70개 새 표본과 기존 Go 70개 표본을 비교했다. 양쪽 실행 시점이 다르고
교차 실행하지 않았으므로 호스트 부하 차이는 남아 있다. DigitalOcean은 시간 변동이 커서
중앙값만으로 우열을 단정하지 않는다.

측정 범위는 컴파일·생성 계획·렌더링·포맷팅·해시 계산까지다.
생성 소스 디스크 게시, 소비자 빌드, TypeScript 타입 검사와 번들링은 포함하지 않는다.
시간은 GNU time의 실제 실행 시간, 메모리는 5회 중 최대 프로세스 RSS다.
앞선 대화와 W11 표의 감시 루프 대기를 제외하고 양쪽 원시 시간 지표를 다시 집계했다.
따라서 기존 표와 소수점이나 짧은 실행 시간이 다를 수 있다.

각 조건의 5개 출력 해시는 모두 같고, 두 타깃의 전체 생성 출력은 독립적인
원본 정확성 감사 결과와도 일치했다. 선택한 10개 경로의 실제 방출도 확인했다.
로컬 측정이며 공개 성능 수치나 모든 입력에 대한 자원 상한을 보장하지 않는다.

## 원본 무결성 확인

임시 디렉터리나 실행 환경 없이 저장소 안의 기록만으로 확인할 수 있다.

```sh
python3 plans/golang-target/measurements/2026-10-19/verify.py
```

`raw/`의 각 파일은 일반 `tar.gz`다. 원래 디렉터리 이름을 구성 경로로 유지한다.
[일회성 측정·집계 스크립트](reproduction/)와 압축 파일 안의
`provider-target-comparison-20261019T003753Z/auditor/main.go`도 보존했다.
일회성 스크립트에는 당시 로컬 경로가 남아 있으므로 재실행할 때 경로를 조정해야 한다.
일반 측정 명령과 워크로드의 기준은 저장소의 `scripts/perf/golang/`이다.
