# 분할 대기 소스의 저장 수명

상태: 최종 후보 기각·제품 코드 복구·근거 보존 완료. 기준 제품은 `5b9312d`와 runtime이 같은 `5627365`다.
단위 13에서 확인한 렌더링 source 보유를 줄인다. 진단용 GC나 제공자 예외를 제품에 넣지 않는다.

## 설계 결정과 계약

분할 대상 두 패키지가 기존 8 MiB 분할 기준에 도달했을 때만 중간 source를 lossless
압축 보관하는 후보를 평가한다. 그 전과 import root가 없어 분할하지 않는 경우는 그대로다.
패키지 소유 encoder를 재사용하고 파일마다 독립된 stream을 저장한다. 원래 source 크기로
분할 기준과 그룹을 계산하고 두 파싱에서 정확히 같은 원본 bytes를 복원한다.
공개 facade·주석·최종 formatter·파일 순서·초기화 순서·오류·반복 emission 독립성을 유지한다.
전체 source를 재렌더링하거나 임시 디스크·전역 cache를 도입하지 않는다.

빠른 표준 flate를 먼저 비교하며 압축 결과가 더 크면 원본을 유지한다. 추가 복호화 CPU와
할당을 포함해 비교하고 시간 손해가 크거나 RSS 이득이 불명확하면 후보를 기각한다.
내부 저장 bytes의 alias·길이·손상 실패를 검증한다. 새로운 공개 설정은 만들지 않는다.

예산은 관련 회귀 검사, 첫 GitHub 전후 1쌍과 retained heap 비교, 유망하면 GitHub 총 3쌍과
TVMaze/ListenNotes 각 1쌍·실제 CLI 검증이다. 기존 cache 4 GiB·scratch 2 GiB,
GOMAXPROCS=4·GOMEMLIMIT=2GiB·개별 180초/RSS 3 GiB를 유지한다.

첫 후보는 전체 출력이 같고 RSS 642,060,288 → 538,288,128 B였지만 시간
35.948 → 39.442초, 할당 18,618,154,112 → 20,573,772,584 B로 증가했다.
이 후보를 채택하지 않고 복원 저장소를 한 번 보완한다. 기존 `io.ReadAll`의 반복 성장과
파일마다 새 flate reader를 만드는 대신, 알려진 원문 길이로 결과를 한 번 할당하고
패키지 소유 decoder를 재사용한다. 이 첫 쌍은 최종 표본에 섞지 않고 source/원시 결과를
`initial-*`로 보존한다. 최종 후보도 시간 손해가 크면 기각한다.

보완 후보 첫 쌍은 RSS 643,825,664 → 516,046,848 B, 시간 39.159 → 36.747초,
할당 18,620,718,696 → 18,947,634,224 B였다. 반복 검증으로 진행한다. observer는
준비 후 입력을 해제하는 GC가 있어 실제 CLI와 다르므로, 제품 채택 전 같은 GitHub로
실제 CLI도 3쌍 비교하는 예산을 추가한다. 생성 파일은 매 실행 검산 후 제거한다.
출력 bytes가 유지되는 경우 생성 SDK의 compiler matrix는 반복하지 않는다.

## 실제 CLI 결과와 기각

관측기의 준비 후 입력 해제 GC가 없는 실제 CLI에서 최종 판단했다. 같은 고정 GitHub·
Go 1.27.2·server addon·import root·메모리/동시성 한도, 새 출력으로 순서를 바꾼 3쌍이다.
각 실행 후 manifest와 실제 6,377개·204,611,637 B 전체 파일을 검산하고 SDK를 삭제했다.

| 지표, 각 3회 중앙값 | 유지한 기존 제품 | 압축 후보 | 변화 |
| --- | ---: | ---: | ---: |
| 생성 시간 | 35.5619초 | 39.5344초 | +11.17% |
| user+system CPU | 39.9784초 | 45.0068초 | +12.58% |
| 최대 process RSS | 638,476,288 B | 589,844,480 B | −7.62% |
| 생성 출력 | 6,377개·204,611,637 B | 동일 | 모든 파일 hash 일치 |

세 쌍 모두 시간이 늘었다(후보/기존 1.11278/1.05888/1.10626).
기하평균 1.09238, 3^3 조건부 재표집 percentile 95% 구간은 [1.06900, 1.11137]이다.
이는 작은 로컬 표본이지 모든 환경의 분포가 아니다. 기준 시간 범위는 35.5276–35.9171초,
후보는 37.6558–39.7339초다. 이 범위에서 약 7.6% RAM 절감을 위해 시간/CPU를 늘리는
교환은 채택하지 않는다. 제품 runtime과 테스트 파일은 기준 상태로 복구했다.

관측기에서는 시간 중앙값 39.1586→38.7214초, RSS 628,936,704→516,046,848 B,
할당 +1.76%였다. 시간 비율 재표집 구간은 1을 포함한다. 선택 지점의 실제 GC 후 heap은
266,839,760→158,207,760 B였지만 peak RSS나 실제 CLI의 메모리 절감률이 아니다.
보유 source의 기여 확인에는 유효하나 제품 채택 수치로 대체할 수 없음을 확인했다.

## 검증·복구·보존

- 최종 관련 회귀 검사 31개와 소유권/race 검사 통과. 원문·크기·경계·그룹·주석·
  독립성·압축 확대 시 원본 유지·손상 및 길이 오류에서 출력 중단을 확인했다.
- 관측기 GitHub 3쌍·TVMaze/ListenNotes 각 1쌍, 실제 CLI GitHub 3쌍·두 작은 API,
  heap 진단의 전체 생성 파일이 유지한 제품과 같다. cold/warm compile은 재측정하지 않았다.
- 첫 최종 driver는 실행 전 Python 괄호 오타로 실패했다. 수정 후 실제 최종 검증은
  통과했으며 원래 실패 로그도 보존했다. 이 실패를 성능 표본에 넣지 않았다.
- 605개 runtime 경로의 Go 파일을 기준 빌드 hash와 대조해 복구를 확인했다.
  후보의 두 신규 Go 파일도 제거했다. 원문 저장·분할 호출자·소유권·오류·정확성·
  실측 경계·기각과 복구를 리뷰했다. 제품 변경을 채택했다는 주장은 없다.
- 후보/기준 실험 실행 파일 5개·184,146,764 B를 정리했다. 사용자의 종료 요청에 따라
  추가 후보는 진행하지 않고 작업 전체 캐시/임시 파일 정리로 이어간다.

전체 종료 정리도 완료했다. 모든 단위의 보존 근거를 검산한 뒤 전용 cache와 남은
실행 파일/임시 파일 전체를 삭제했다. [최종 비교](final-comparison.md)에 결과를 기록했다.
