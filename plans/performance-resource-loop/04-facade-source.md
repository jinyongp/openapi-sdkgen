# Facade AST의 원본 소유권과 중복 출력 제거

상태: 구현·관련 검사·실측 검산·실제 CLI 통합·최종 리뷰 완료.
공개 주석 손실을 수정하고 중간 전체 포맷을 제거했다.

기준 제품은 `6c1365c`다. 앞서 수집한 profile에서 본문과 호출 수가 같은 facade
경로를 확인했다. 함수 전체는 약 3.72 GiB의 sampled 누적 할당, 6.89 CPU초였고,
중간 `format.Node`에 약 2.24 GiB·4.63 CPU초가 귀속됐다. 과거 profile의 함수 단위
원인 근거이며 현재 후보의 개선율로 쓰지 않는다.

기존 facade는 implementation용 AST를 포맷한 바이트를 다시 파싱하여 독립된 AST를
만들었다. 호출 직전 이미 immutable 원본 바이트가 있고, 첫 implementation AST는
아직 재작성하지 않았다. 후보는 그 원본을 직접 파싱한다. facade와 implementation의
AST 독립성, 공개 서명·상수·alias·문서와 최종 정규 포맷은 유지한다. AST cache나
수명 연장을 추가하지 않는다.

조사 예산은 관련 검사, 실제 입력 예비 1쌍, 근거가 있으면 GitHub 최대 3쌍과 작은
두 입력의 정확성 확인이다. 같은 observer와 직렬 실행·단일 Go cache를 사용한다.
cache 4 GiB·생성물 2 GiB, GOMAXPROCS=4·Go soft heap 2 GiB·session RSS 보호
3 GiB·개별 180초 상한을 유지한다. 현재 cache는 약 2.2 GiB다.

## 출력 차이 조사와 검증 기준

첫 GitHub 쌍은 생성 자체는 성공했지만 byte inventory 대조에 실패했다. 기준
47.1911초·24,327,440,608 B 누적 할당, 후보 39.8307초·22,005,742,608 B였으나
이 예비 1쌍은 최종 표본에 섞지 않는다. 양쪽 6,377개 파일이며 후보 출력은
203,199,878→204,611,637 B로 증가했다. 변경된 공통 경로 313개와 서로 다른
packed 경로 각 109개가 있었다. 단순 공백이라고 분류하거나 hash 예외를 추가하지 않았다.

작은 재현에서 원인은 원본 AST와 연결되지 않은 빈 `FileSet`으로 첫 출력을
만드는 기존 경로였다. 주석이 본문 중간으로 밀리고 facade에서 제거되기도 했다.
새 `TestPartitionFacadePreservesDocumentation`은 입력의 package·상수·type·함수
문서를 독립적으로 기대한다. 수정 전 네 문서 모두 사라져 실패했고 후보는 통과했다.
원본 직접 파싱은 이 결함을 고치면서 중간 전체 포맷을 없애는 구조적 변경이다.

기존 버그로 없어진 문서까지 제거해 byte 동일성을 맞추지 않는다. 이번 단위는
문서 복원을 명시적 출력 변화로 기록한다. 파일 크기 변화에 따른 기존 packing
경계·경로 이동까지 검증해야 한다. 새 정확성 검사는 전체 Go 선언의 AST를 package별로
비교한다. 주석·위치·packed 파일 배치만 제외하고 식별자·리터럴·연산자·alias·
variadic 호출·모든 실행 본문과 선언별 import binding을 보존해야 한다.
compiler/build directive는 별도로 보존한다. 이는 생성 SDK 런타임 성능 측정이 아니다.
검증 helper의 차이 감지 자체도 변형 입력으로 확인한다. 관련 generated race 소비자
검사와 세 실제 API의 전체 선언 비교를 통과하기 전에는 채택하지 않는다.

기존 실패와 진단은 `original-source-prototype.tar.gz`에 보존했다(40항목,
1,642,579 B, SHA-256 `efd51086861b1e19830f2a8b31f8c51c33bb45495f8c891474331b0d50d8828c`).
생성 출력은 inventory 보존 후 제거했다. 추가 예산은 검증 helper 확인·기준 출력
재생성 1회·최종 실제 입력 비교로 제한하며 같은 자원 상한을 유지한다.

## 실제 입력 비교

같은 phase observer 소스와 빌드 옵션으로 직전 확정 제품 `6c1365c`와 최종 후보를
빌드했다. GitHub는 3쌍을 기준→후보, 후보→기준, 기준→후보로 실행했고 작은 두
입력은 각 1쌍이다. CPU/heap profiling은 켜지 않았다. 입력 hash·server addon·
`example.test/graph/api`·Go 1.27.2·GOMAXPROCS=4·GOMEMLIMIT=2GiB는 같았다.
observer의 입력 해제 GC·출력 hash·게시까지 포함한다. 별도 AST 검산 비용은 아래
생성 측정에 포함하지 않았고, 검산은 측정 뒤 직렬로 실행했다.

GitHub 각 3회 중앙값:

| 지표 | 직전 제품 | 후보 | 변화 |
| --- | ---: | ---: | ---: |
| 실행 시간 | 44.9030초 | 40.1149초 | −10.66% |
| user+system CPU | 50.6516초 | 45.4280초 | −10.31% |
| 누적 할당 | 24,325,807,232 B | 22,005,747,136 B | −9.54% |
| 최대 개별 프로세스 RSS | 603.36 MiB | 607.87 MiB | +0.75% |
| 출력 크기 | 203,199,878 B | 204,611,637 B | +0.69% |

시간 범위는 기준 44.0725–49.6958초, 후보 39.9023–40.1575초다. 대응 비율은
0.80293/0.89337/0.91117, 기하평균은 0.86783이다. 3^3 재표집의 선형 보간
percentile 95% 구간은 [0.82183, 0.90729]다. 작은 로컬 표본의 재표집 결과이며
모든 환경의 개선율이나 정밀한 모집단 신뢰구간으로 일반화하지 않는다.

누적 할당은 약 2.32 GB 줄었지만 동시 점유 메모리와 다르다. RSS 범위는 기준
601.09–606.27 MiB, 후보 607.43–612.92 MiB였다. 세 쌍 모두 후보가 높았으며
최대 RSS 절감으로 표현하지 않는다. GC 설정을 수치에 맞춰 바꾸지 않았다.
공개 문서와 줄 배치를 복원해 출력 약 1.41 MB가 늘어난 비용도 유지한다.
문서 손실을 되살리지 않으면서 중간 전체 출력/재파싱을 제거하고 CPU·할당을 줄이는
현재 변경을 채택한다. 앞 단위의 개선율에 더해 누적 개선율로 안내하지 않는다.

GitHub는 양쪽 모두 6,377개 파일이다. 최종 후보의 모든 표본은 파일별 byte/hash가
서로 같았다. 55개 package의 선언 471,516개와 초기화 선언 4,581개의 AST·순서가
기존과 일치했다. TVMaze는 143개·3,172,460 B, ListenNotes는 201개·7,546,903 B이며
양쪽 전체 byte/hash와 코드가 일치했다. 작은 입력 각 1쌍의 시간으로 개선율을 주장하지 않는다.

## 리뷰와 검증

| 영역 | 완료 근거 |
| --- | --- |
| 원인·설계 | 유일한 호출자는 아직 수정하지 않은 implementation AST와 원본 바이트를 가진 emitter다. 원본에서 facade를 다시 파싱하여 두 AST의 소유권과 위치 집합을 분리한다. AST cache·수명 연장·제공자 예외를 추가하지 않는다. |
| 문서·주석 | 독립 기대값 검사에서 기존 package/상수/type/함수 문서 손실을 재현했다. 최종 후보는 네 문서를 보존하고 detached 본문 주석을 제거하며 정규 Go 포맷을 통과했다. |
| 실행 코드 | 표준 parser로 모든 Go 파일을 읽었다. 위치는 유효 여부를 유지해 alias `Assign`·호출 `Ellipsis`를 구분한다. 선언의 모든 이름·리터럴·연산자·본문과 사용하는 import 연결, package별 초기화 순서와 blank import를 대조했다. compiler/build/line directive와 Go 이외 관리 파일은 별도로 대조했다. 세 입력에서 모두 일치했다. |
| 비교기 | alias/정의·리터럴·variadic·selector·import 연결·초기화 순서 변형을 구분하고 주석/줄 배치 변화는 같게 처리하는 자체 검사를 통과했다. full compiler/type checker나 SDK 실행 성능 측정을 대신하는 도구로 안내하지 않는다. |
| 소비자·소유권 | 최종 `TestPartition*`·`TestPack*`와 `internal/output` 전체 검사 통과. 생성 소비자 race, 게시 rollback·편집 파일 보호·stale 파일 정리 검사를 포함한다. |
| 실측 검산 | 고유 표본 10개·전체 inventory·같은 observer·입력/바이너리/스크립트/로그/source hash·게시 checkpoint를 대조했다. runtime 제품 변경은 `partition.go` 하나이며 검사 후 바뀌지 않았다. |
| 실제 CLI 통합 | 최종 CLI로 같은 import root·server 옵션의 세 실제 입력을 각 1회 생성했다. 관리 파일 집합과 모든 파일 hash가 독립 observer 후보와 일치했다. CLI SHA-256은 `8360f68837493d69624da240e303a1f756391b7b02a289a25aac237c353e4aed`다. 단일 정확성 확인이며 새 성능 표본으로 집계하지 않는다. |
| 자원 | 최종 전용 cache 약 2.3 GiB, cache를 뺀 scratch 약 704 MiB, Go 임시 경로는 비어 있다. 4 GiB·2 GiB 상한 안이며 검산 후 생성 SDK를 제거했다. |

최초 byte 대조 실패와 수정 전 결함 재현 실패는 보존하고 최종 성능 표본에 섞지
않았다. 파일·패키지 인자를 한 `go build`에 섞은 준비 명령도 실패했으며 두 빌드로
나누어 성공했다. 제품 실패로 분류하거나 실패 기록을 덮어쓰지 않았다.

전체 Graph·Cloudflare·전체 compiler/corpus 매트릭스·다른 플랫폼·TypeScript와
생성 SDK의 HTTP·cold/warm 컴파일 비용은 새로 측정하지 않았다. 공개 문서에는
로컬 개선 수치를 게시하지 않는다.

## 보존

[원시 근거](measurements/04-facade-source.tar.gz)는 20,894,268 B,
근거 항목 285개와 색인 1개다. SHA-256:
`9087674ac82379e1bcf07bec13caa60a9efc680cdde7031ea6e1eea251187518`.
모든 항목을 다시 읽어 크기·hash를 검증했다. 전체 선언 fingerprint 목록도 보존해
다른 단위보다 크지만, 동일 내용은 archive 내 hardlink로 한 번만 저장한다.
서로 다른 원본 내용은 합계 39,902,112 B로 64 MiB 상한 안이다.
기준/후보 빌드 원본 목록·명령·측정·실패·AST 비교기와 자체 검사·CLI 확인을 포함한다.
SDK 전체 출력·실행 파일·Go cache는 넣지 않았다.
archive의 전체 항목 검증 후 중복 raw 선언 목록 10개(199,947,166 B)는 archive 색인의
원본 hash를 대조하고 작업 임시 경로에서 제거했다. 원본 전체는 archive에 유지한다.
