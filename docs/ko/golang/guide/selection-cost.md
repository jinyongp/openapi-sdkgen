# 선택과 빌드 비용

<span id="선택-방식과-컴파일-비용"></span>


Go 링커는 도달할 수 없는 코드를 제거합니다. import한 패키지의 초기화는 남을 수 있고,
컴파일러는 import한 패키지를 계속 처리합니다. JavaScript 트리 셰이킹이나 브라우저 다운로드
청크 크기는 Go 빌드 설정이 아닙니다. 목적에 맞는 범위를 선택하세요.

| 선택 | 용도 | 비용 범위 |
| --- | --- | --- |
| 루트 클라이언트 | 여러 API를 폭넓게 사용 | 선택된 전체 소스 의존성 |
| 이름 있는 클라이언트 | 고정된 기능 경계 | 독립 진입점과 공유 패키지 |
| 정적 `operations` 참조 + `selective` | 작업별 구체 타입 | 코드에서 쓰는 참조를 import |
| `LookupOperation` / `LookupRoute` | 실행 중 계산한 선택 | 지연 초기화하는 동적 레지스트리와 동적 값 |
| 선택 생성 | 미리 아는 API 부분집합 | 출력 소스와 컴파일 작업 감소 |

생성할 때 입력 파싱과 분석은 여전히 필요합니다. 선택한 API 수만큼 메모리가 비례해서 줄지는
않습니다. 압축·스키마·URL 의존성에도 별도의 컴파일·메모리 비용이 있습니다.
생성, SDK 컴파일, 실행 중 할당, 최종 실행 파일 크기를 나누어 측정하세요.

## 같은 조건으로 빌드 비교

```sh
go clean -cache
go build -o ./app .
go build -o ./app .
go test -bench . -benchmem ./...
```

첫 빌드는 빈 캐시에서, 두 번째는 캐시를 재사용해 실행합니다. Go 버전·플랫폼·입력·확장·선택 API·
빌드 옵션을 맞추고 실행 시간·최대 메모리·출력 파일 수와 크기·컴파일 시간·실행 파일 크기를
각각 기록하세요. 소스 크기만으로 일정한 속도 향상을 추정하지 마세요.
선택 문법은 [필요한 API 선택](./selective-client.md)과 [이름 있는 클라이언트](./named-clients.md)에 있습니다.
