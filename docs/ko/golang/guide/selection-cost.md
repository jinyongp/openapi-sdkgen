# 선택과 빌드 비용

<span id="선택-방식과-컴파일-비용"></span>


Go 링커는 도달할 수 없는 코드를 제거합니다. import한 패키지의 초기화는 남을 수 있고,
컴파일러는 import한 패키지를 계속 처리합니다. JavaScript 트리 셰이킹이나 브라우저 다운로드
청크 크기는 Go 빌드 설정이 아닙니다. 목적에 맞는 범위를 선택하세요.

| 선택 | 용도 | 비용 범위 |
| --- | --- | --- |
| 루트 클라이언트 | 여러 API를 폭넓게 사용 | 선택된 전체 소스 의존성 |
| 이름 있는 클라이언트 | 고정된 기능 경계 | 독립 진입점과 공유 패키지 |
| 정적 `operations` 참조 + `selective` | 작업별 구체 타입 | 코드에서 쓰는 참조를 import |
| `LookupOperation` / `LookupRoute` | 실행 중 계산한 선택 | 지연 초기화하는 동적 레지스트리와 동적 값 |
| 선택 생성 | 미리 아는 API 부분집합 | 출력 소스와 컴파일 작업 감소 |

생성할 때 입력 파싱과 분석은 여전히 필요합니다. 선택한 API 수만큼 메모리가 비례해서 줄지는
않습니다. 함께 생성하는 스키마·URL·Unicode 코드에도 컴파일·메모리 비용이 있습니다.
작업 수가 적어도 HTTP 클라이언트에는 URL 정규화 코드가 필요합니다. 정적 패턴은 생성할 때
컴파일하며, 실행 중 패턴을 받는 서버 스키마나 `regex` 형식 검증이 있을 때만 정규식 컴파일러를
포함합니다.
생성, SDK 컴파일, 실행 중 할당, 최종 실행 파일 크기를 나누어 측정하세요.

## 같은 조건으로 빌드 비교

POSIX 셸에서는 다른 프로젝트의 빌드 캐시를 유지하도록 임시 캐시를 사용하세요.

```sh
build_cache="$(mktemp -d)"
GOCACHE="$build_cache" go build -o ./app .
GOCACHE="$build_cache" go build -o ./app .
rm -rf "$build_cache"
go test -bench . -benchmem ./...
```

첫 빌드는 별도로 만든 빈 Go 빌드 캐시를 사용하며 표준 라이브러리 빌드도 포함합니다.
두 번째는 소스를 바꾸지 않고 그 캐시를 재사용합니다. 운영체제의 파일 캐시는 비우지 않습니다.
다른 셸에서는 임시 디렉터리 생성과 환경 변수 설정 문법을 해당 셸에 맞추세요.
무변경 빌드가 빨라져도 API 수정 후 다시 컴파일하는 시간이 줄었다는 뜻은 아닙니다.
Go 버전·플랫폼·입력·확장·선택 API·
빌드 옵션을 맞추고 실행 시간·최대 메모리·출력 파일 수와 크기·컴파일 시간·실행 파일 크기를
각각 기록하세요. 소스 크기만으로 일정한 속도 향상을 추정하지 마세요.
선택 문법은 [필요한 API 선택](./selective-client.md)과 [이름 있는 클라이언트](./named-clients.md)에 있습니다.

## 생성 파일과 변경 비용

생성한 선언 여러 개가 하나의 소스 파일에 들어갈 수 있습니다. 파일 수가 줄면 파일을
처리하는 부담은 줄어들 수 있지만, 소스 바이트·컴파일러 메모리·컴파일한 패키지 파일·
최종 실행 파일 크기가 같은 비율로 줄지는 않습니다. API 하나를 바꿔도 함께
들어 있는 더 큰 파일을 다시 쓸 수 있습니다. Go는 컴파일한 패키지를 캐시하므로 파일 수
감소만으로 변경 후 빌드 비용이 줄었다고 판단할 수 없습니다.
파일 수가 줄어도 생성 시간은 늘어날 수 있습니다.

같은 문서와 옵션으로 기존·새 생성기를 번갈아 반복 측정하세요. 생성 시간은 새 출력에서
측정하고, 빈 캐시 빌드·무변경 캐시 재사용·소스 수정 후 빌드를 나누어 비교하세요.
메모리도 측정 범위를 명시해야 합니다. 개별 프로세스의 최대 RSS, 동시에 실행되는
프로세스들의 합, 실행 후 남는 힙은 서로 다른 지표입니다.
RSS를 합하면 공유 페이지가 중복 집계될 수 있습니다.
[공개 호환성 검증 결과](../reference/compatibility.md)는 측정한 Actions 실행에 연결됩니다.
기록한 검증의 근거이며 생성기 버전 사이의 성능 개선율을 뜻하지는 않습니다.
