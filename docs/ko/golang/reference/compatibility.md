생성·컴파일 성공만으로 제공자 서버가 모든 요청을 받아들이거나 생성된 모든 호출을 실행했다고
판단할 수는 없습니다.

측정 워크플로는 Go 클라이언트와 서버 핸들러를 별도로 생성하고, 생성된 모듈에서
`go test ./...`를 실행합니다. 생성 차단과 컴파일 오류는 실패로 기록합니다.
생성만 측정하는 Microsoft Graph 결과는 이 Go 검증에서 제외하며, 제공자 API를 호출하지는 않습니다.

각 결과에는 컴파일 자원과 제한 시간을 기록합니다. 현재 측정은
[공개 저장소용 표준 Linux 실행기](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)에서
패키지를 하나씩 빌드하며, CPU 스레드 4개, Go 소프트 메모리 한도 6 GiB,
컴파일 제한 시간 20분을 사용합니다. 소프트 한도는 프로세스 메모리의 상한이 아닙니다.
과거 결과에는 당시 조건을 그대로 보존합니다. 조건이 다른 결과로 성능을 비교하지 않습니다.

생성 근거를 먼저 저장한 뒤 컴파일합니다. 실행기가 종료돼 컴파일 결과를 회수하지 못한
문서는 **미검증**으로 표시합니다. 이 상태는 해당 입력의 Go 컴파일 지원을 보장하지 않습니다.

DigitalOcean이 공개한 작성용 명세에는 Operation Object 자체의 참조가 있어 생성 전에
번들링이 필요합니다. 측정 시 원본과 전처리 결과의 해시를 모두 보존하고, 컴파일 후 작업 식별자·
필수 매개변수·응답 표현의 보존 여부를 검사합니다. DigitalOcean 태그 정규식의 불필요한
콜론 이스케이프와 Spoonacular의 경로·쿼리 매개변수를 중복한 빈 미디어 타입 본문은
명시적으로 정한 규칙에 따라 보정하고 결과 해시를 고정합니다. 유효한 요청 본문은 유지하며,
스키마 전체의 동등성을 보장하는 전처리는 아닙니다.
보정한 제공자는 독립적으로 만든 로컬 HTTP 서버에 클라이언트 요청을 보내 전송 데이터,
검증 실패와 HTTP 오류 처리도 확인합니다. 실제 제공자 서버를 호출하지는 않습니다.

## 자신의 명세 검증

```sh
openapi-sdkgen generate --input ./openapi.yaml --target golang \
  --go-import-path example.com/consumer/internal/api --output ./internal/api --check
go test ./...
```

출력 디렉터리가 없으면 먼저 생성하세요. 웹훅·콜백에는 `--with server`를 추가합니다.
모의 서버나 제공자의 시험 환경에서 실제 호출과 미디어를 확인하고 입력 버전·선택 API·확장·
Go 버전을 기록하세요. 비용 비교는 [선택과 빌드 비용](../guide/selection-cost.md)을 참고하세요.
